# Share Text Agent Conventions

## Development Guide

Read this `AGENTS.md` and the applicable shared reference files under `$AI_CONFIG_DIR/references/*.md` before writing or reviewing code. When reviewing code, follow the `code-review` skill definition, reporting findings with severity, location, rule, and fix. When instructions are ambiguous about what to change or how to approach a task, ask the user to clarify or present up to three concrete options before making changes, to avoid unwanted edits.

## Project conventions

- Code changes are applied in a separate git branch and worktree under `.worktrees/` per the shared `references/git.md` worktree practice, unless the user opts to apply them on top of the current worktree.
- Server persistence goes through the `Db` interface (`src/lib/server/db-types.ts`), writing engine-agnostic SQL with `$n` placeholders and `current_timestamp` so DDL stays portable across adapters. Follow the SQL conventions in `references/sql.md` (including binding a placeholder once per occurrence).
- Mutations are logged via `$lib/server/logging` with key identifying info (document id, name, size, IP, `elapsed_ms`).
- Document tags are stored as a JSON array of `{ name, color }` objects in the `documents.tags` column; `color` must be one of the hex `TAG_COLORS` in `src/lib/tag-colors.ts`, and chips/dropdowns render via the `tagChipStyle`/`tagDotStyle` inline-style helpers there (class helpers `tagChipClass`/`tagDotClass` carry the non-colour base styles). Tag badges render with the `Chip` component (`src/lib/components/Chip.svelte`).
- Document types follow the shared `type-registry` reference: the closed value set lives in `src/lib/document-type-values.ts`, the type definitions (language extensions, validators, formatters, converters, preview, toolbar actions) in `src/lib/document-types.ts`, and pure parse/format utilities in `src/lib/document-type-utils.ts`. Each type entry lazy-loads heavy dependencies (language modes, parsers) via dynamic `import()` inside the definition so they are not in the initial bundle. Consumers dispatch through `getDocumentType(value)` and never branch on specific type values.
- Editor preview modes are driven by the `preview`/`editor` URL query params via `usePreviewMode` (`src/lib/components/use-preview-mode.svelte.ts`). On desktop the toolbar shows two toggle buttons (Editor view with a pencil icon / Preview view with an eye icon) instead of a cycle button: each carries `aria-pressed` and switches its button variant to show on/off state, and is `disabled` when it is the sole active pane (so the panes can never be both off). Toggling on always lands in split view. On mobile there is no split view: the hook normalizes any non-editor mode to preview-only (`effectiveMode`), and a single eye-icon preview toggle (`togglePreview`) flips between editor-only and preview-only; the desktop two-button split toggles are not rendered. When the current document type has no preview support, the buttons and preview params are ignored for layout (the editor fills the full pane).
- Editable form dialogs (settings, tags, format) use the OK/Apply + Reset pattern from the shared `ui-patterns` reference.
- Content version history: creating a document records its initial state as the first `document_versions` snapshot, and a save that changes `content` or `document_type` appends another (content, type, `created_by`, `created_at`). Version rows are keyed by the immutable numeric `documents.id` (`document_id bigint references documents(id) on delete cascade`), so an admin key change leaves versions attached to the same document and never requires migrating rows; the version queries resolve the app-facing key to that numeric id via a subquery. Only the newest `max_document_versions` snapshots are kept per document (env `MAX_DOCUMENT_VERSIONS`, default 20; admin-adjustable); older rows are pruned on the same save. Versions are deleted with their document (explicitly in `deleteDocument`, and by the FK cascade on Postgres). The editor toolbar shows a History button (clock icon) only when the document has 2+ versions (`versionCount`, refreshed by the editor page after each save). It opens `HistoryDialog`, which lists versions newest-first, loads the selected version's content on demand for a read-only view, and offers two icon buttons with tooltips: Compare with current (splits the content pane in two — selected version left, current editor content right, each pane showing its own document type tag above the content, since versions can differ in type) and Restore (copies the version's content+type back into the editor as unsaved changes, confirmed first when the editor is dirty). On mobile the dialog is full screen (`fullscreen` prop on `BaseDialog`, driven by the `isMobile` context passed from the editor pane) instead of a centered modal. The action panel stays visible so the dialog height is fixed across all versions and states. The content pane and the loading spinner use a fixed `h-[60vh]` (the version list stays capped at `max-h-[70vh]`), so the dialog never resizes when switching between versions of different content lengths — long content scrolls inside the pane via `overflow-auto`. The dialog itself never needs a scrollbar even on short viewports: the `BaseDialog` children wrapper, the dialog root, the list/content row (`md:h-[60vh]`), and the content pane are all `min-h-0` flex items, so when the fixed `60vh` pane plus the dialog chrome would overflow `BaseDialog`'s `max-h-[90vh]`, flexbox shrinks the pane to fit automatically — no hard-coded chrome reservation. The Compare and Restore buttons are disabled (and show no tooltip) whenever there is nothing to act on — no version selected yet, a version still loading, or the selected version already matches the current editor content and type. The buttons stay in place while a version loads so the panel never resizes; only the disabled state changes, so Restore can never act on a stale version.
- Overlay option panels (dropdowns, tag suggestions) position via the shared `positionPanel` action (`src/lib/position-panel.svelte.ts`): attach it to the panel with `use:positionPanel={() => ({ getTrigger: ..., getOpen: ..., align?, autoPlace? })}` and keep the `fixed left-0 top-0 z-50 will-change-transform` positioning classes on the panel. The action portals to `document.body`, auto-places above/below, and repositions on resize/scroll; components keep their own open/close, keyboard, and outside-click handling. The `KebabMenu` component (`src/lib/components/KebabMenu.svelte`) follows this pattern for a three-dot action menu: it takes `items` (`{ id, label, onClick, disabled?, icon? }`), keeps its own open state, and closes on item click, Escape, outside pointer-down, and scroll.
- The CSV grid model (`src/lib/components/use-grid-model.svelte.ts`) tracks a per-cell `committed` flag. Arrow navigation past the last row/column appends *pending* rows/columns whose cells stay uncommitted until a value is typed (`setValue`/paste/major structural ops mark cells committed), so pure navigation never serializes trailing empty cells into the CSV; `matrix()` bounds itself to the committed region and `pruneTrailingPendingRows`/`pruneTrailingPendingColumns` drop empty pending rows/columns on navigate-away, Escape, or mouse click. Keep the self-echo reconciliation too: incoming `value` that differs from the last committed matrix only by trailing all-empty rows (the `parseCsv` round-trip drops them) is treated as a self-echo so committed-but-empty rows (e.g. toolbar inserts) survive the preview content feedback; a genuine external change with different data rows still rebuilds the grid.
- The `DataGrid` component (`src/lib/components/DataGrid.svelte`) renders the grid for the CSV and Properties previews. It accepts `maxColumns` to lock the grid to a fixed column count (disabling column insert/delete/append, nav growth, and trimming, and clamping pastes to it), `columnLabels` to show custom header labels instead of column letters, `hideHeaderToggle` when the grid type has no header row (e.g. Properties), and `initialColumnWidths` (percentage strings, px numbers, or omitted) to switch the table to `table-layout: fixed` with explicit widths. The column label row (topmost header row) also sorts data rows: each header cell hosts two separate arrow buttons (same up/down icons as the admin `DataTable`) revealed on hovering the cell, the active column keeps its arrows always visible with the active direction tinted cyan, and clicking the up arrow sorts ascending while the down arrow sorts descending (no toggle). Sorting goes through `model.sortRows(columnIndex, direction)`, which uses the natural `compareGridValues` (numeric cells numerically, otherwise locale-aware) and skips the header row when headers are on — the header stays pinned while only the rows below reorder. The reorder commits through the normal commit path, so it is undoable and reflected in `onChange`. The sort indicator is a snapshot of the sort column taken at sort time; editing any cell in that column invalidates it and hides the sort status (arrows fall back to hover-only, `aria-sort` cleared) so the user can resort. The grid's outer edges come from the table's `border-t`/`border-l` only, so cells keep single-edge borders (`border-r`/`border-b`) and any column-width math must subtract `TABLE_LEFT_BORDER` (1px) to keep the table's border box inside the scroll container. Cell editing is spreadsheet-style: a single click only selects the cell; double-clicking enters edit mode with the cursor after the last character, and double-clicking again while editing selects all text (`handleCellDoubleClick` in `use-grid-selection.svelte.ts`). While a cell is being edited, mouse interaction inside it behaves like a normal text input (caret placement / in-cell text selection); grid range-dragging only works from a non-editing cell.
- Effects that reconcile an external input into editable `$state` (e.g. `CsvPreview` re-parsing `content` into grid rows) follow the `$effect` state-write guard from the shared `svelte` reference: track the last consumed input so each change is parsed at most once, since non-round-trippable text (like content shown after a type switch) would otherwise loop forever.
- The admin `DataTable` (`src/lib/components/DataTable.svelte`) sorts like the grid header: each sortable column header cell hosts two separate up/down arrow buttons revealed on hovering the cell (`group` class lives on the `th`), the active column keeps its arrows visible with the active direction tinted cyan, and clicking the up arrow sorts ascending while the down arrow sorts descending (no toggle). `handleSortClick(column, direction)` passes the explicit direction through `onSort`; the label itself is not a sort trigger. Column sizing prefers the `width`/`minWidth` props (`widthClass`/`minWidthClass` override them when given): a number is pixels, a string ending in `%` is a percentage (rebased so percentage columns sum to 100% before the `width` is applied), and any other string must be a valid CSS length — malformed width/min-width values are ignored and reported to the console. The derived width/min-width are applied as inline `style` on the cells (never as utility classes built at runtime — see the shared `tailwind` reference); those inline minimums keep core columns (Key, Name, attribution, timestamps) from collapsing below a readable width when the panel narrows; overflow is handled by the container's horizontal scroll and the table's `min-w` floor. A `fillHeight` prop makes the table fill the available flex height instead of the fixed `containerClass` cap (overriding it): the root becomes a `min-h-0 flex-1` column and the scroll container drops its `max-h` for `min-h-0 overflow-auto` (the search box and pagination stay pinned via `shrink-0`), so the table is capped at the available space without being forced to stretch.
- The browser layout (`src/routes/(browser)/+layout.svelte`) is responsive. Below the `md` breakpoint (767px, driven by a `matchMedia`-backed `isMobile` `$state` exposed through the share-text context) the split panes collapse into full-screen pages with no splitter: the document list occupies the whole screen when no editor is open (on `/`), and opening a document (route `/[id]` or `/new`) hides the list and shows the editor full screen. On mobile the `DocumentEditorPane` header stacks into three rows — document name + right-aligned type selector, then the tag chips, then the action buttons — and both the tag and action rows `flex-wrap` when horizontal space runs out; the first row is itself a wrapping flex where the name keeps a usable width (`flex-1` with `min-w-[min(12rem,60%)]`), so the type selector drops to its own row when the screen is too narrow for both. On mobile the action row opens with a `KebabMenu` (three-dot) holding the Upload, Export, History, and Format actions in that order (History only when the document has 2+ versions; the menu owns the `FormatDialog`), followed by the preview toggle and the Copy, Clone, Tags, Reset, and Save toolbar buttons (Clone only when available). On desktop the toolbar shows the TypeActions plus the Copy, Clone, History, Upload, Export, Format, Tags, Reset, and Save buttons (History between Clone and Upload, Format between Export and Tags, Reset directly before Save). On desktop the header lays the name/tags group, the type selector, and the (self-wrapping) button panel out in one wrapping flex (content-driven wrapping per the shared `responsive-design` reference): the name/tags group uses `flex-basis: min-content` and the type selector is a separate right-anchored item, so when the pane narrows enough that the button panel would crowd the type selector the panel wraps to its own row (left-aligned, since the shared row is kept flush-right by the name group filling the space) and the type selector stays right-aligned at the end of the first row; the buttons can themselves span multiple rows. The desktop split-pane/collapse behavior is unchanged; `DocumentList` sizes itself full-width on mobile via `w-full` (the inline `width` style is only set on desktop), and the list header's collapse button is hidden below `md`. The left pane header (both the expanded `DocumentList` header and the collapsed strip) shows a Login button after the Refresh button that navigates to `/login`, so admin sign-in is reachable from the document browser.
- The admin console (`src/routes/admin/`) routes its Properties/Documents tabs as real SvelteKit routes: `/admin` redirects (`+page.server.ts`) to `/admin/properties` when the admin session is authenticated and to `/login` when it is not, and `/admin/properties` and `/admin/documents` exist as empty `+page.svelte` shells so each tab keeps a stable, shareable URL. The tab chrome is rendered by the generic `Tabs` component (`src/lib/components/Tabs.svelte`): a `Tab<TState>` entry provides a `label`, `path`, `toolbar` snippet, and `content` snippet, each of which can take the shared state; `Tabs` renders the tab bar (marking the active path with `aria-current="page"`), the active tab's toolbar, and the active tab's content. The auth shell and the `useAdminSettings`/`useAdminDocuments` instances live in `src/routes/admin/+layout.svelte`, which builds the two admin tab entries (toolbar/content snippets render the shared `AdminPropertiesView`/`AdminDocumentsView` with the state passed as props) and renders `<Tabs tabs={...} state={...} pathname={page.url.pathname} />` — the layout stays mounted across tab navigation so the settings draft and documents data survive tab switches, and the documents list lazy-loads via a layout `$effect` on the documents path. The `beforeNavigate` discard guard lets navigations within `/admin` through without prompting, since the shared state survives tab switches. The admin layout renders no top header row until `authState` is `authenticated` (the header only carries the app/tab chrome). When the session is gone — the session check returns unauthenticated, or an `AdminAuthError` surfaces from the settings/documents state (session timeout), or the user signs out — `authState` flips to `unauthenticated` and the layout redirects to `/login` unless it is already there. The pre-login page lives at `/login` (`src/routes/login/+page.server.ts` redirects authenticated sessions to `/admin/properties` and returns the `configured` flag otherwise; `+page.svelte` renders the shared `LoginPanel`), and a successful sign-in there navigates to `/admin/properties`, so the app only lands on the Properties tab once authenticated.
- Temporary scratch files created during work (plans, proposals, scratch notes) go in the `.tmp/` folder, never in source directories.

## Keeping references in sync

- When a code change establishes or revises a project-specific convention, update this `AGENTS.md` in the same change.
- When a code change establishes or revises a generic reusable convention, update the appropriate file under `$AI_CONFIG_DIR/references/` in the same change rather than duplicating it here.
 - Shared reference files under `$AI_CONFIG_DIR/references/` must remain generic and implementation-agnostic. Do not include project-specific file paths, component names, routes, or other internal identifiers in those references — put project-level details in this `AGENTS.md` instead. See `ai/references/README.md` for the brief style guide.
